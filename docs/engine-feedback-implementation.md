# Calculation engine: client feedback implementation report

Specification: workbook TC-DOM-002a v0.1 (Scope 1–2). Scope: the client's four questions on the factor library, plus the ten-part implementation brief. The work was done inside the existing architecture: no rebuild, nothing removed, no record deleted.

## 1. Status of every client concern

| # | Concern | Status | What was done |
|---|---|---|---|
| 1 | Biogenic: which field carries it; does the engine read the note? | **Done** | `ActivityType.carbonOrigin` (tab 02 column) is the structured field and drives C-02, the biogenic memo line and the non-fossil CH₄ GWP. The note text is never read. A record can now also carry an origin: V-02 and V-17 are enforced, and blends ("Mixed") are supported. |
| 2 | NCV and density in free text; where does a site enter monthly lab NCV? | **Done** | NCV and density are now structured columns with their published value, unit and source. The engine reads only those columns. New **Fuel Properties** register: monthly lab values per fuel and facility, with certificate, approval and versions. |
| 3 | AR5/AR6: what decides the set; how does a report state it? | **Done** | New `gwpSet` and `gwpBasis` columns. Selection uses the column, not the source-version text. The set is chosen per run (AR6 by default; AR5 needs a reason), stored on the run with its basis (GWP-100), and printed in reports and audit entries. |
| 4 | EF-9999 (coal per ton-hour); is the library platform-wide? | **Done** | Factors are validated against the workbook's own activity/unit mappings on creation and on editing, and checked again at selection. Invalid rows are never used. The library now distinguishes **shared** factors (Super Admin) from **organisation-specific** ones (Tenant Admin, visible only to that organisation). Factors have a Draft/Active/Withdrawn lifecycle. EF-9999 is not deleted: run the audit script (section 7) and withdraw it with a reason if it is unused. |
| 5 | "Steam & removals: 0 factors" | **Done** | The tab now explains what each activity needs: a supplier-specific factor for steam, heat and cooling; a direct metered quantity for CO₂ removals. Organisations can store their supplier's factor as their own library factor; C-21 uses it when the record has none. |

## 2. Database changes

One additive migration: `backend/prisma/migrations/20261110120000_factor_lifecycle_fuel_properties`. No column is dropped or altered and no row is deleted.

- **EmissionFactor**
  - New columns: `status` (DRAFT/ACTIVE/WITHDRAWN, default ACTIVE), `organizationId` (null = shared), `gwpSet`, `gwpBasis`, `approvedById`/`approvedAt`, `withdrawnById`/`withdrawnAt`/`withdrawnReason`, `updatedAt`.
  - Backfill: `gwpSet` is set on the 33 GWP rows (17 AR6, 16 AR5).
  - Every existing factor stays **ACTIVE and shared**. Ownership can't be inferred from the data, so nothing was made private.
- **ActivityType:** `defaultNcvPublished`, `defaultNcvSource`, `defaultDensity`, `defaultDensityUnit`, `defaultDensitySource` (the existing `defaultNcv` is kept, in TJ/t).
- **FuelProperty** (new table): organisation, facility, fuel, month, version, status (DRAFT/APPROVED/REJECTED/SUPERSEDED), NCV, density and unit, carbon content, oxidation factor, biogenic share, certificate reference, laboratory, sample date, certificate file (stored outside the web root with its SHA-256), created by, reviewed by, review note.
- **CalculationRun:** `gwpBasis` (default "GWP-100").
- **MySQL (live):** the schema is regenerated by `scripts/mysql-schema.mjs` (long text fields widened). The reference seed backfills `gwpSet` and the structured NCV and density on databases that have no migrations.

## 3. API changes

Existing endpoints keep their behaviour. `POST /api/platform/emission-factors` still creates an active factor by default.

| Endpoint | Who | Purpose |
|---|---|---|
| `GET /api/reference/emission-factors` | signed in | Now visibility-scoped; new filters `scope` and `status`; each row has `shared`, `status`, `usable` and `problem`; tabs carry `explanations` |
| `GET /api/reference/emission-factors/:id/history` | signed in (visible factors) | Created / edited / activated / withdrawn, by whom, when and why, plus usage count |
| `POST /api/emission-factors` | Tenant Admin (`factor.manage`) | Organisation-specific factor |
| `PATCH /api/emission-factors/:id` | owner | Edit a **draft** only (an active factor returns 409) |
| `POST /api/emission-factors/:id/activate` | owner | Draft → Active |
| `POST /api/emission-factors/:id/withdraw` | owner | Withdraw with a mandatory reason; returns usage counts |
| `GET/POST /api/fuel-properties` | read: all roles; write: `fuel.write` | Monthly lab values |
| `POST /api/fuel-properties/:id/certificate`, `GET …/certificate` | `fuel.write` / read | Certificate file |
| `POST /api/fuel-properties/:id/approve`, `…/reject` | `fuel.approve` | Review. Not by the person who entered the value (Tenant Admin excepted); a certificate is required |
| `GET /api/reference/activity-types` | signed in | Adds `factorShapes` (the gas and units a factor for the activity may take) |

"Owner" means a Super Admin for shared factors, or the organisation's Tenant Admin for its own. Another organisation's factor returns 404. New permissions: `factor.manage`, `fuel.write`, `fuel.approve`.

## 4. Engine changes

- **Factor validation** (`calc/core/factorRules.ts`)
  - The allowed (gas, unit, per-unit) combinations per formula are derived from the workbook's tab 04 rows, including the rows the SME left blank (steam/heat/cooling); there is no hand-written list.
  - Grid and supplier-heat factors also accept units of the same dimension, which tab 03 converts.
  - The same check runs on create, edit, activation and selection. At selection, a factor is used only if it is ACTIVE, shared or the organisation's own, and fits its formula.
- **Fuel values** (C-01/02/03), in order of use:
  1. value entered on the record (tab 05 rule 5)
  2. approved monthly register value (rule 1)
  3. workbook default, which needs a confirmation (J-04)

  V-09 blocks only when no density is available "(user or default)", as tab 10 states. A liquid density (kg/l) is never applied to a gas volume.
- **Tier 3 CO₂:** the CO₂ factor is derived from the lab carbon content: CO₂ = mass × C × 44/12 × oxidation (IPCC 2006 vol.2 ch.1; oxidation defaults to 1). An own CO₂ factor is also accepted per consignment. V-11 warns beyond ±10% of the IPCC factor, or when no source is given. **CH₄ and N₂O remain IPCC Tier 1 defaults**, so this is Tier 3 for CO₂ only.
- **Monthly register rules**
  - Applied only when the record lies inside one calendar month; otherwise FP-02 is reported and the register is not used.
  - Values awaiting approval are never used, and FP-01 says so.
  - The register row's id, version and certificate are stored in the result's inputs.
- **Blends:** origin "Mixed" with a biogenic share of carbon, from the record (with certificate) or the register. Validation:
  - the share must be strictly between 0 and 100
  - if a fossil share is given, the two must add up to 100
  - evidence is required (J-12, J-16)

  CO₂ is split: the fossil part counts in Scope 1, the biogenic part goes to the memo line. CH₄ uses the share-weighted fossil and non-fossil GWP.
- **C-21:** uses the record's supplier factor, else the organisation's own active supplier factor, else blocks with V-19. Shared steam factors are refused.
- **Reports:** the GWP set **and basis**, plus each factor's GWP set, library (shared or organisation) and current status. Gross emissions, the biogenic memo and removals stay separate lines, and removals are never netted (G-05, G-06).

The 3 MySQL failures are environmental or unrelated to this work, and were verified, not assumed:

- **1 reconciliation ordering test:** items created in the same millisecond have no tiebreaker on MySQL. The file was not touched by this work and is worth a separate one-line fix.

One factor-list ordering difference found on MySQL was fixed (a code tiebreaker).

New tests (`backend/tests/factor-engine.test.ts`) cover all 15 requested areas:

- monthly Tier 3 selection (approved/draft/versions/multi-month/other facility)
- carbon-content CO₂ and V-11

## 8. Historical records

- No record, result, run or factor was deleted or modified by the migration or the code.
- Stored results keep their factor id, factor value and inputs.
- Withdrawing a factor or approving a new fuel-property version affects only runs made afterwards. Both are tested by re-reading earlier results.
- Superseded fuel-property versions are kept.
- Existing factors remain active and shared, so calculations on existing data produce the same numbers. The all-NCV comparison showed 0 differences across 66 fuels.

## 9. Decisions and open questions for the SME

1. **Blend method.** The biogenic share is treated as a share of the fuel's *carbon*. The blended fuel's own factors are split by that share, and CH₄ takes the share-weighted fossil/non-fossil GWP. The workbook's C-02 note says the "fossil share of a blend goes through C-01" but doesn't say which factors the biogenic share uses. Please confirm, or name the factors.
2. **Stationary LPG (A-ST-LPG).** It's measured in SCM (gas volume), but its quoted density, 0.54 kg/L, is for the liquid. The engine won't apply it to a gas volume, so SCM entries need a certificate density. Should the activity be measured in litres or kg, or should a gas density be given?
3. **Oxidation factor.** It defaults to 1 (IPCC 2006). Confirm, or give a site-specific value.
4. **Multi-month records.** Monthly lab values apply only to single-month records. A quarterly record falls back to defaults with a notice. Is a quantity-weighted rule wanted instead?
5. **Missing workbook values:** CH₄/N₂O for road biodiesel and bioethanol, A-BIOM and A-REFR, the AR5 non-fossil CH₄ GWP, and landfill (Q-06). These stay blocked until the SME supplies values.
6. **Approval rule for the register and factors.** A Tenant Admin may approve their own entry (as for activity records); others may not. A factor is activated by its owner with no second person. Is four-eyes wanted for factors?
7. **Tier 3 coverage.** Site CO₂ only. Site-specific CH₄ and N₂O are not supported.
8. **Tab 12 (Open Questions)** is empty in the delivered workbook, although the engine references Q-02 and Q-06. Please confirm where those decisions are recorded.
